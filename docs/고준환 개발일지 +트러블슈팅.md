# OnePass 프로젝트 개발일지

**작성자:** 고준환

**프로젝트 개요:** 동백전과 일반 카드를 통합 관리하고, 카드별 혜택 비교 및 유리한 결제수단 추천과 모의결제를 제공하는 핀테크 서비스

---

## 1. 개발 환경 및 배포 구성

| 구분 | 기술 스택 | 역할 |
|---|---|---|
| 프론트엔드 | Next.js, React, TypeScript | 사용자 화면 및 기능 구현 |
| UI | Tailwind CSS, Lucide React | 스타일링 및 아이콘 |
| 백엔드 | Python, FastAPI | REST API 및 비즈니스 로직 |
| ORM | SQLAlchemy | DB 연동 및 데이터 처리 |
| 데이터베이스 | PostgreSQL (NeonDB) | 카드·가맹점·혜택·결제 데이터 저장 |
| 프론트엔드 배포 | Vercel | 웹 서비스 배포 |
| 백엔드 배포 | Render | FastAPI 서버 배포 |

### 시스템 구성

```text
사용자
  │
  ▼
프론트엔드 (Next.js / Vercel)
  │
  ▼ REST API
백엔드 (FastAPI / Render)
  │
  ▼ SQLAlchemy
데이터베이스 (PostgreSQL / NeonDB)
```

## 3. 백엔드 REST API 개발

FastAPI 기반으로 카드 관리, 혜택 조회, 가맹점 조회, 결제 추천 및 거래 내역 API를 구현함.

### API 버전 관리

향후 ERD에 테이블이나 컬럼이 추가되어 API 요청·응답 구조가 변경될 경우 유지보수가 용이하도록 `/api/v1`을 적용함.

기존 API와 호환되지 않는 변경이 필요한 경우 `/api/v2`를 추가하여 기존 기능을 유지하면서 신규 API를 개발할 수 있도록 고려함.

### 주요 API 목록

모든 API는 `/api/v1`을 공통 경로로 사용함.

| 구분 | Method | API 경로 | 기능 |
|---|---|---|---|
| DB | GET | `/health/db` | DB 연결 확인 |
| 카드 | GET | `/cards/products` | 카드 상품 목록 |
| 카드 | GET | `/cards/products/{product_id}` | 카드 상품 상세 |
| 사용자 카드 | GET | `/users/{user_id}/cards` | 등록 카드 목록 |
| 사용자 카드 | DELETE | `/users/{user_id}/cards/{user_card_id}` | 등록 카드 해제 |
| 혜택 | GET | `/benefits/products/{product_id}` | 카드별 혜택 규칙 |
| 혜택 | GET | `/benefits/{rule_id}` | 혜택 규칙 상세 |
| 가맹점 | GET | `/merchants` | 가맹점 목록 |
| 가맹점 | GET | `/merchants/{merchant_id}` | 가맹점 상세 |
| 결제 | POST | `/payments/recommend` | 유리한 카드 추천 |
| 결제 | POST | `/payments` | 모의결제 처리 |
| 결제 | GET | `/payments/{tx_id}` | 거래 상세 |
| 거래이력 | GET | `/users/{user_id}/payments` | 사용자 거래 내역 |

향후 위치 기반 서비스와 브랜드별 혜택 조회를 고려하여 `merchant` 테이블에 7개 컬럼을 추가함.

## 5. REST API 예외 처리

| 예외 상황 | 처리 결과 |
|---|---|
| 결제 내역이 없는 사용자 | 빈 목록 반환 |
| 존재하지 않거나 다른 사용자 소유의 카드 삭제 | `404 Not Found` |
| 이미 해제된 카드 재삭제 | `404 Not Found` |
| 해제된 카드 목록 조회 | 조회 대상에서 제외 |
| 등록되지 않은 카드로 결제 요청 | 카드 없음 오류 메시지 |
| 다른 사용자 카드로 결제 요청 | `403 Forbidden` |
| 중복 결제 요청 | `409 Conflict` |
| 존재하지 않는 거래 조회 | 예외 처리 |

## 6. 주요 트러블슈팅

### 6-1. 동백전 결제 후 잔액 미차감 및 캐시백 미반영

**문제 발생**
- 동백전 결제 후 잔액이 차감되지 않고 예상 캐시백이 0원으로 표시됨.

**원인**
- `PaymentService`에서 지갑 잔액 차감 로직이 누락됨.
- 예상 혜택과 실제 결제 혜택의 계산 기준이 일치하지 않음.
- Render에서 수정 전 커밋이 실행되는 배포 버전 불일치 확인.

**해결 과정**
- Render의 배포 커밋을 확인하고 최신 코드로 재배포함.
- `PaymentService`의 지갑 잔액 차감, 캐시백 계산, 거래 원장 저장 로직을 수정함.
- 예상 혜택과 실제 혜택에 동일한 계산 기준을 적용하도록 개선함.

**결과**
- 결제 처리 로직과 배포 버전 간 불일치를 개선함.
- 결제 오류 분석 시 코드뿐 아니라 실제 서버에서 실행 중인 배포 버전도 확인해야 함을 파악함.

### 6-2. CORS 설정 오류로 인한 로그인 요청 차단

**문제 발생**
- Vercel 및 로컬 환경에서 로그인 API 호출 시 Preflight 요청이 HTTP 400으로 차단됨.

**원인**
- FastAPI의 CORS 허용 출처 설정이 실제 프론트엔드 실행 주소와 일치하지 않음.
- Render 환경변수에 설정한 프론트엔드 주소가 정상적으로 반영되지 않음.

**해결 과정**
- Render의 `FRONTEND_URL` 환경변수에 Vercel 및 localhost 주소를 등록함.
- FastAPI의 `CORSMiddleware` 설정을 수정하여 허용 출처를 일치시킴.
- 프론트엔드에서 로그인 API 요청이 정상적으로 처리되는지 확인함.

**결과**
- Preflight 요청 차단 문제를 해결함.
- 프론트엔드와 백엔드를 서로 다른 도메인에 배포할 때 CORS 설정과 환경변수 관리가 중요함을 확인함.

### 6-3. 일반 카드 혜택 산정 오류 및 결제 처리 범위 결정

**문제 발생**
- 일반 카드의 예상 혜택이 `혜택 산정 불가`로 표시됨.
- 신용카드 결제 후 이용가능한도가 감소하지 않는 현상이 발생함.

**원인**
- NeonDB의 `card_month_close` 테이블에 전월 실적 데이터가 누락됨.
- 일반 카드 결제 원장은 정상 저장되지만 신용카드 한도 및 체크카드 잔액 차감 기능은 구현되지 않은 상태였음.

**해결 과정**
- `card_month_close` 테이블에 카드별 전월 실적 데이터 3건을 등록함.
- 일반 카드의 한도 및 잔액 차감 기능을 추가할지 검토함.
- 현재 MVP는 카드별 혜택 비교와 모의결제가 핵심이므로 별도 한도·잔액 관리 기능은 구현 범위에서 제외함.
- 모의결제 승인 및 거래 내역 저장 기능은 유지함.

**결과**
- 전월 실적 데이터 등록을 완료함.
- 혜택 산정 정상화 여부는 추가 검증이 필요함.
- 신용카드 한도 관리와 체크카드 잔액 차감은 향후 개선사항으로 분류함.

### 6-4. 메인화면 카드 캐러셀 무한 순환 시 화면 끊김 문제

**문제 발생**
- 마지막 카드에서 첫 번째 카드로 전환할 때 슬라이드가 역방향으로 되돌아가는 현상이 발생함.
- 카드가 한 방향으로 자연스럽게 이어지는 무한 캐러셀 구현이 필요했음.

**원인**
- 기존 캐러셀은 카드 배열의 시작과 끝이 시각적으로 연결되지 않은 구조였음.
- 마지막 카드에서 첫 번째 카드로 돌아갈 때 슬라이드 위치가 초기화되어 이동 방향의 연속성이 깨짐.

**해결 과정**

이동 방향 변수 `d`를 사용하여 오른쪽 이동은 양수, 왼쪽 이동은 음수로 구분함.

**이동 예시 1 — 오른쪽으로 7칸 클릭**

- 카드 4장, 현재 3번째 카드 (`cur_idx = 2`)
- 이동 칸수: `d = 7`
- 이동 경로: `2 → 3 → 0 → 1 → 2 → 3 → 0 → 1`
- 계산: `(2 + 7) % 4 = 1`
- 최종 인덱스: `1`

**이동 예시 2 — 왼쪽으로 7칸 클릭**

- 카드 4장, 현재 3번째 카드 (`cur_idx = 2`)
- 이동 칸수: `d = -7`
- 이동 경로: `2 → 1 → 0 → 3 → 2 → 1 → 0 → 3`
- 계산: `(2 - (7 % 4) + 4) % 4 = 3`
- 최종 인덱스: `3`

양수와 음수 이동을 구분하고, 음수 이동에서는 절댓값과 나머지 연산을 적용하여 유효한 카드 인덱스를 계산하도록 설계함.

```text
if (d >= 0)
    new_idx = (cur_idx + d) % cards.length
else if (d <= -1)
    temp_d = Math.abs(d)
    temp_d = temp_d % cards.length
    new_idx = (cur_idx - temp_d + cards.length) % cards.length
```

- 원본 카드 4개를 3세트로 복제하여 총 12개의 슬라이드 요소를 구성함.
- 실제 슬라이드 위치를 활성 카드 인덱스와 별도로 관리함.
- 복제 카드 구간으로 이동한 뒤 CSS transition을 일시적으로 비활성화하여 가운데 카드 세트로 위치를 보정함.
- `requestAnimationFrame`을 활용하여 위치 보정 이후 transition을 다시 활성화함.
- `setInterval`을 사용하여 3초 간격의 자동 슬라이드를 구현함.

**결과**
- 왼쪽·오른쪽 이동 시 카드 인덱스가 올바르게 순환하도록 계산 방식을 정리함.
- 복제 슬라이드와 위치 보정을 결합하여 화면 끊김 없는 무한 캐러셀을 구현함.
